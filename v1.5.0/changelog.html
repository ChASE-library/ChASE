v1.7.5

2026-11-17 · Configurable rescaling of pseudo-Hermitian initial random vectors and RCCL constructor warm-up

Documentation · GitHub release

ChASE Library Release Notes

v1.7.5 (compared to v1.7.4)

Overview

This release makes the lower-half scale $\gamma$ of a random pseudo-Hermitian initial guess configurable, and it fixes the GPU constructor warm-up so that an RCCL-only AMD build keeps it. The CMake project version is now 1.7.5, so generated headers and pkg-config report that version.

The default scale remains $\gamma = 0.001$. Hermitian problems and approximate restart do not use it. Release and RelWithDebInfo builds still leave the constructor warm-up disabled.

🎯 Main Changes
1. Configurable pseudo-Hermitian initial lower-half scale $\gamma$

The lower block of a random pseudo-Hermitian initial guess was fixed at $\gamma=0.001$. ChaseConfig now stores this factor, still defaulting to 0.001.

  • SetInitLowerScale and GetInitLowerScale set and read it.
  • The CPU, GPU, and both distributed implementations use it when the initial guess is random and the problem is pseudo-Hermitian.
  • Zero clears the lower block. One leaves the random entries unchanged.
  • C chase_set_init_lower_scale_ and Fortran chase_set_init_lower_scale set it for whichever precision is active.
  • This factor is independent of the Chebyshev lower-bound decaying rate.
2. AMD constructor warm-up

The pChASEGPU constructor benchmark warm-up was compiled only when HAS_NCCL was defined. An RCCL-only AMD build therefore dropped it.

The guard is now HAS_NCCL or HAS_RCCL, together with CHASE_GPU_CONSTRUCTOR_BENCHMARK_WARMUP. The warm-up body still selects the NCCL backend type, which is the type used by the RCCL path. CUDA/NCCL builds keep the same warm-up.

3. Version reported by the build

project(... VERSION ...) is now 1.7.5. After configuration, CHASE_VERSION in chase_config.h and Version in chase.pc follow that number. The README checkout example is v1.7.5.

📦 Additional Changes
  • update CITATION.cff.
📌 Migration Notes
  • Existing configurations keep the lower-half scale at 0.001.
  • Applications that need another value call SetInitLowerScale, chase_set_init_lower_scale_, or chase_set_init_lower_scale before solving.
  • AMD Benchmark builds that already request CHASE_GPU_CONSTRUCTOR_BENCHMARK_WARMUP=ON now run the constructor warm-up. Release and RelWithDebInfo builds still do not.

v1.7.4

2026-10-26 · Improved Static Linking and GPU QR Reliability

Documentation · GitHub release

ChASE Library Release Notes

v1.7.4 (compared to v1.7.3)

Overview

This release improves integration for downstream applications, fixes GPU QR event handling and timing, and migrates the GPU CI pipeline to JUPITER.

It also includes an initial experimental CUDA/Hopper integration of the Ozaki-II GEMMul8 filter backend. The complete adaptive Ozaki-II implementation remains under development and is not part of this release.

🎯 Main Changes

1. Improved pkg-config Support

chase.pc now exports the public ChASE libraries and the complete static backend dependency closure, including CUDA/NCCL or HIP/RCCL, ScaLAPACK, BLAS, LAPACK, MPI, OpenMP, and the C++ runtime.

Static downstream consumers can now use:

pkg-config --static --libs chase

OpenMP CMake handling was also corrected to avoid forwarding incompatible host compiler flags through NVCC.

2. GPU QR Timing Fixes
  • Avoid querying unrecorded CholQR events in the Householder path
  • Fix invalid resource handle errors in output-enabled CUDA builds
  • Correctly measure and report explicit Householder core time
3. JUPITER CI Migration
  • Move GPU CI jobs from JUWELS Booster to JUPITER
  • Use the JUPITER scratch filesystem and runner tags
  • Build for CUDA architecture 90
  • Explicitly load ScaLAPACK in GPU build, test, and coverage jobs

📦 Additional Changes

  • Add CHASE_DISABLE_EARLY_LOCKING to disable the early-locking heuristic
  • Add an initial, opt-in experimental Ozaki-II/GEMMul8 CUDA backend
  • Existing CPU, CUDA, and HIP behavior remains unchanged by default

The adaptive precision and dynamic modulus-selection work from the Ozaki-II development branch is not included in this release.

🧪 Testing

The static-linking and GPU QR changes were validated through Yambo on one JUPITER node using four MPI ranks and four NVIDIA GPUs.

The validation covered output-enabled and production builds, Householder and CholQR paths, and CPU/GPU numerical comparisons. All regression checks passed without CUDA event errors.

📌 Migration Notes

  • Existing configurations remain unchanged by default.
  • Static consumers should use pkg-config --static --libs chase.
  • The experimental Ozaki-II backend is disabled by default and should not

yet be considered the complete adaptive implementation.

v1.7.3

2026-09-15 · Support for AMD GPUs (HIP/ROCm)

Documentation · GitHub release

ChASE Library Release Notes

v1.7.3 (compared to v1.7.2)

Overview

This release adds production-grade AMD GPU (HIP/ROCm) support to ChASE, together with a unified CUDA/HIP GPU architecture. Serial and distributed GPU solvers now share the same algorithm layers and dispatch to NVIDIA or AMD backends. NVIDIA/CUDA paths are preserved. The mathematical algorithm is unchanged from v1.7.2. The port was validated on Frontier, including Hermitian and pseudo-Hermitian (BSE) problems.

🎯 Major Features

1. AMD GPU (HIP/ROCm) Support
  • HIP backend for ChASEGPU (serial GPU) and pChASEGPU (distributed GPU)
  • rocBLAS / rocSOLVER wrappers under external/amd_gpu/
  • Distributed GPU communication on AMD:
  • RCCL collectives (default, NCCL-compatible xCCL path)
  • HIP-aware MPI as an alternative
  • Hermitian and pseudo-Hermitian (full BSE) solvers on HIP, serial and distributed
  • C and Fortran interfaces wired to the HIP backend
  • Validated on Frontier: serial HIP, HIP-aware MPI, RCCL, and Example 4 C/Fortran interface runs
2. Unified CUDA/HIP GPU Architecture
  • GPU internals reorganized under linalg/internal/gpu/:
  • backend/: runtime, BLAS, solver, context, workspace planning
  • serial/: shared CholQR, Lanczos, Rayleigh–Ritz, residuals + CUDA/HIP wrappers
  • dist_mpi/: GPU-aware MPI path (CUDA-aware and HIP-aware)
  • dist_xccl/: NCCL (NVIDIA) and RCCL (AMD) path
  • kernels/: shared device kernels with CUDA/HIP specializations
  • Shared implementations for HEMM, CholQR, Lanczos, RR, residuals, and symOrHerm
  • GPU-resident workspace reuse and execution-context ownership for handles/streams/devInfo
  • NVIDIA CUDA/NCCL behavior retained and adapted to the new dispatch layer
3. Distributed GPU Collectives and Timing
  • RCCL discovery, build wiring, and distributed kernel layer mirroring NCCL
  • Stream-aware synchronization on GPU-aware MPI hot paths
  • Corrected HIP/RCCL timing for filter and QR phases (event placement/ordering)
  • Reduced over-conservative barriers where correctness allowed
4. Documentation and Benchmark Tooling
  • AMD/ROCm install and CMake guidance in the user docs
  • Architecture notes: docs/amd_gpu_port_architecture.md
  • Frontier collective benchmark docs and matrix-operations benchmark (MPI/xCCL modes)
  • Helper scripts: scripts/frontier_hip_env.sh, scripts/run_hip_*.sh

📦 Build & Configuration

CMake Improvements
  • External wrappers grouped by platform: external/cpu, external/nvidia_gpu, external/amd_gpu, external/scalapack
  • FindRCCL.cmake for RCCL detection
  • HIP autodetection via check_language(HIP)
  • chase_config.h now exposes HIP / HIP-aware MPI / RCCL flags
Configuration Options
  • CHASE_ENABLE_HIP: AUTO (default), ON, or OFF
  • CHASE_HIP_DISTRIBUTED_COLLECTIVES: NCCL (RCCL on ROCm, default) or MPI
  • CHASE_PROBE_HIP_AWARE_MPI_RUNTIME: optional configure-time HIP-aware MPI probe (default: OFF)

Example HIP build:

cmake .. \
 -DCHASE_ENABLE_HIP=ON \
 -DCHASE_HIP_DISTRIBUTED_COLLECTIVES=NCCL

On NVIDIA-only machines, CUDA detection is unchanged. Use -DCHASE_ENABLE_HIP=OFF to skip HIP autodetection.

🔍 Logging & Diagnostics

  • Rank-0 logging guards in distributed CholQR and interface config output (less multi-rank noise)
  • Additional Frontier bring-up diagnostics for HIP/RCCL collectives

🧪 Testing

  • HIP serial unit tests (CholQR, Lanczos, Rayleigh–Ritz, residuals, kernels)
  • HIP-aware MPI distributed tests (HEMM, Lanczos, QR, RR, residuals, pseudo-Hermitian)
  • RCCL tests mirroring the NCCL suite
  • Serial/distributed C and Fortran interface smoke tests on HIP
  • Frontier helper scripts for serial, distributed, e2e, and interface runs

🔗 API Changes

  • QR(cond): dropped unused fixednev argument
  • Resd(ritzv, resd): dropped unused fixednev argument
  • ReinitColumns(base_col, col_indices, n_indices): parameter renamed from fixednev to base_col
  • Public solver classes are unchanged: ChASEGPU, pChASEGPU, C/Fortran interfaces
  • pChASEGPU communication backend: chase::grid::backend::MPI or chase::grid::backend::NCCL (maps to NCCL on NVIDIA, RCCL on AMD)

📌 Migration Notes

For Users Upgrading
  • HIP is opt-in via CMake; existing CUDA builds should keep working
  • Typical usage remains one GPU per MPI rank
  • Distributed HIP Householder QR uses the ScaLAPACK fallback (native HIP Householder QR is not in this release)
  • NVIDIA XGEEV for pseudo-Hermitian RR remains CUDA-only (CHASE_ENABLE_XGEEV_RAYLEIGHRITZ)
For Developers / Downstream Includes

Old CUDA-only headers moved. Update includes, for example:

  • external/cublaspp/ → external/nvidia_gpu/cublaspp/
  • external/blaspp/ → external/cpu/blaspp/
  • linalg/internal/cuda/ → linalg/internal/gpu/serial/cuda/ and linalg/internal/gpu/kernels/
  • linalg/internal/nccl/ → linalg/internal/gpu/dist_xccl/nccl/
  • linalg/internal/cuda_aware_mpi/ → linalg/internal/gpu/dist_mpi/cuda/

👥 Contributors

This release includes work by Xinzhe Wu, with major efforts in:

  • AMD/HIP port on Frontier
  • Unified CUDA/HIP GPU backend
  • RCCL and HIP-aware MPI distributed paths
  • HIP test coverage and documentation

v1.7.2

2026-05-05 · Interior eigenvalue support for pseudo-hermitian problems and built-in multi-GPU HouseholderQR

Documentation · GitHub release

ChASE Library Release Notes

Overview

This release represents significant advancements in the ChASE (Chebyshev Accelerated Subspace Extraction) library, with major enhancements to pseudo-Hermitian matrix support to compute interior eigenpairs with eigenvalues around 0, distributed-memory GPU capabilities, QR factorization algorithms, and user interfaces.

🎯 Major Features

1. Pseudo-Hermitian Matrix Support
  • Extended ChASE to compute lower excited states of full Bethe-Salpeter Equation (BSE) matrices
  • Implemented positive-negative symmetry handling in ChASE-CPU, ChASE-GPU, pChASE-CPU and pChASE-GPU
  • Improved locking mechanism for negative components with K-conjugate operation
  • Added damping factor for lower block initialization to improve numerical stability
  • Paper on arxiv: Chebyshev Accelerated Subspace Eigensolver for Pseudo-hermitian Hamiltonians
2. Distributed-Memory GPU Support (pChASE-GPU)
  • GPU-resident Lanczos implementation with fused kernels
  • Optional warm-up procedures in constructor for NCCL initialization
3. Advanced Householder QR Factorization
  • CUDA-aware-MPI and NCCL Householder QR: Two-level padding/cleaning strategy with full-path diagnostics
  • Level-1: Panel pre-clean (coarse)
  • Level-2: Column split-and-pad (fine)
  • Full-height GEMM updates with NCCL allreduce
  • Distributed CPU Householder QR:
  • cpu_distributed_houseQR_panel_factor_block_cyclic_1d
  • cpu_distributed_blocked_houseQR_formQ_block_cyclic_1d
4. Enhanced Fortran/C Interfaces
  • Added second initializer for Fortran interfaces (internal buffer management)
  • Users no longer need to provide external buffers for eigenvectors/eigenvalues
  • Configuration setter functions added to Fortran/C interfaces
  • Support for both block-block and block-cyclic distributions simultaneously

📦 Build & Configuration

CMake Improvements
  • Minimal drivers are split into chase_driver_cpu (links chase_cpu, and cublaspp/cusolverpp when CUDA is enabled so shared headers link cleanly) and chase_driver_gpu (links chase_gpu when CUDA is enabled); the old single target chase_driver is removed.
  • Made ScaLAPACK optional
  • Added pkg-config support
  • Improved CMake configuration with chase_config.h.in
  • Default CUDA architectures: 80;90 (Ampere and Hopper)
Configuration Options
  • Environment variable support for Householder parameters
  • CHASE_PH_LANCZOS_DIAG: Optional damping factor info print (default: OFF)

🔍 Logging & Diagnostics

  • Centralized ChASE logger introduced
  • Replaced direct stdout with configurable logging
  • Log levels: Trace, Debug, Info, Warning, Error

🧪 Testing

  • Added Fortran interface tests
  • Full runs of all builds in unit tests

🔗 API Changes

New Unified Configuration Setters

All precision/matrix-type independent:

chase_set_tol(tol)
chase_set_deg(deg)
chase_set_max_deg(max_deg)
chase_set_max_iter(max_iter)
chase_set_lanczos_iter(lanczos_iter)
chase_set_num_lanczos(num_lanczos)
chase_set_approx(flag)
chase_set_opt(flag)
chase_set_cholqr(flag)
chase_enable_sym_check(flag)
chase_set_cluster_aware_degrees(flag)

📌 Migration Notes

For Users Upgrading

1. ScaLAPACK is now optional: Distributed Householder QR is the default 2. Logger API: Direct printf/cout calls replaced with GetLogger().Log() 3. Configuration: Fortran: new unified setters work across all precision/matrix types 4. Fortran buffers: Optional external buffers - library can manage internally

👥 Contributors

This release includes contributions from Edoardo Di Napoli, Clément Richefort and Xinzhe Wu, with major efforts in:

  • Pseudo-Hermitian extensions
  • Distributed GPU implementations
  • NCCL-based linear algebra
  • Interface improvements

v1.7.1

2026-03-10 · Stabilized GPU Lanczos, BLACS Context Fixes

Documentation · GitHub release

This minor release focuses on stabilizing GPU/NCCL Lanczos and QR workflows, tightening MPI/BLACS integration, and strengthening tests and build configuration.

Highlights

GPU/NCCL performance & stability: More GPU-resident Lanczos with warm-up phases for Lanczos/QR, fused kernels, async host copies, and better CUDA error reporting. MPI/BLACS correctness: BLACS contexts are now correctly bound to the user’s MPI communicator, fixing issues when using sub-communicators. Robust testing & CI: Broader unit test coverage (including Fortran interfaces), more complete test runs, and stabilized CI across configurations. Better configuration & packaging: Added pkg-config support and chase_config.h.in for easier downstream integration.

New & Improved

Implemented fully GPU-resident Lanczos with fused kernels and warm-up phases for Lanczos and QR when using NCCL. Cleaned up GPU kernels and enabled async host copies to reduce overhead. Improved examples and interfaces, including updates to 1_hello_world.cpp and new/updated Fortran interface tests. Added pkg-config support and chase_config.h.in to streamline configuration and discovery of ChASE from external projects. Introduced chase_config infrastructure for more flexible build-time configuration.

Bug Fixes

Fixed a critical bug by binding BLACS contexts to the user’s MPI communicator, ensuring correct behavior with sub-communicators. Resolved multiple issues in GPU-resident Lanczos, including stream handling in chase_gpu and bugs in Lanczos with NCCL. Fixed a typing issue for single-precision eigenvalue vectors in the Fortran interface. Fixed build problems for the GPU version when NCCL is not present, allowing clean builds with or without NCCL. Added explicit CUDA kernel error retrieval to aid debugging and robustness.

Testing & CI

Added full runs of all builds into unit tests, including GPU and NCCL combinations. Expanded and stabilized Lanczos unit tests and related test files.

v1.6.0

2025-01-28 · ChASE code structure fully revised

This release has no Sphinx documentation. · GitHub release

ChASE has gone a complex restructuring process that included major changes in the hierarchical folder structure, a clearer division between parallel implementations and a new Test-Driven-Development which introduced unit testing for many of its routines. In particular:

  • A clear division between Chase algorithm and their implementation has been maintained
  • The name of the base virtual class has changed from Chase to ChaseBase
  • All Implementation for sequential and parallel CPU/GPU architecture has been clearly separated and based on the new ChaseBase class.
  • All reliance on external numerical libraries (BLAS, LAPACK, etc.) has been separated and templated
  • Utilities for the initialization of pure MPI, cuda-aware MPI and NCCL grids has been redefined and clearly separated
  • Implementation of the kernels have been grouped in a linalg folder which contains
  • matrix classes for shared-memory CPU and GPU architectures
  • matrix classes for distinct distribution of matrices and vectors
  • shared memory kernels
  • distributed CPU kernels
  • single GPU kernels
  • distributed GPU kernels
  • Functionalities for mixed precision have been added
  • Unit testing has been introduced for
  • the grid functionalities
  • matrix type functionalities
  • all kernels for the separate cases (CPU, GPU, distributed CPU, etc.)
  • Examples have been generalized and redistribution of matrices has been abstracted
  • A template for Collaboration Agreement (CLA) has been added

v1.3.0

2023-03-10 · ChASE v1.3.0. Major release.

Documentation · GitHub release

This release features a number of changes in the parallel implementation and the algorithm.

  • The QR factorization, which was previously done redundantly on each MPI process, is not parallelized on a 1D sub-grid of the 2D MPI cartesian grid.
  • As a consequence of the additional parallelization, the number and structure of the workspace buffers has changed greatly diminishing the memory footprint of the entire library
  • The use of the postApplication function has been substituted with the result that some of the communication is now hidden behind computation during the execution of the Rayleigh-Ritz kernel and the Residual kernel
  • The parallel HouseholderQR algorithm has been substituted with the CholeskyQR algorithm (and its more stable variants). A mechanism to avoid failure of this algorithm has been introduced based on numerical analysis results.
  • A new parallel random generator has been added to reduce the time spent initializing the computation, especially for large scale problems.
